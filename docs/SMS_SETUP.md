# 문자(SMS) 취합 설정 가이드

여러 안드로이드 폰에 오는 문자를 자동으로 서버에 모아, **인증번호 / 계좌입금 / 카드결제승인**
세 가지로 분류해 각 화면에서 관리하는 기능입니다.

- 📩 인증번호 → **[인증번호]** 화면 (48시간 후 자동 삭제)
- 🏦 계좌입금 → **[입금관리]** 화면 (계좌 끝 4자리로 구분)
- 💳 카드결제승인 → **[카드사용내역]** 화면 (카드 끝 4자리로 카드별 구분)

> ⚠️ **안드로이드 폰만 가능합니다.** 아이폰(iOS)은 앱이 문자 내용을 읽을 수 없어 이 방식으로 전달할 수 없습니다.

---

## 1단계 — API 키 발급

1. 관리자 계정으로 로그인 → **[시스템 설정]** 화면으로 이동.
2. API 키를 하나 발급하고, 표시되는 **키 값을 복사**해 둡니다. (한 번만 보이니 안전한 곳에 보관)
   - 폰이 여러 대여도 **키 하나를 공용으로** 써도 되고, 폰별로 따로 발급해도 됩니다.

---

## 2단계 — 안드로이드 문자 전달앱 설치

아래 중 하나를 설치합니다(무료로 충분합니다).

- **SMS Forwarder** 계열 ("문자 → URL 전달" 앱) — 가장 간단
- **MacroDroid** — 쉬운 UI
- **Tasker** — 세밀한 제어(고급)

설치 후, 앱에 **문자 수신 권한**을 허용합니다.

---

## 3단계 — 전달 규칙 만들기

"**문자를 받으면 → 아래 주소로 전송(POST)**" 규칙을 만듭니다.

- **주소(URL)**: `https://<배포도메인>/api/sms/inbound`
  - 로컬 테스트라면 PC와 폰이 같은 와이파이일 때 `http://<PC의_IP>:3000/api/sms/inbound`
- **방식(Method)**: `POST`
- **헤더(Header)**: `x-api-key: <1단계에서 복사한 키>`
- **본문(Body)** — 아래 둘 중 아무거나:

**JSON 방식** (`Content-Type: application/json`)
```json
{ "text": "{문자본문}", "sender": "{발신번호}", "device": "대표폰" }
```

**폼 방식** (`Content-Type: application/x-www-form-urlencoded`)
```
text={문자본문}&sender={발신번호}&device=대표폰
```

- `{문자본문}`·`{발신번호}` 자리에는 앱이 제공하는 변수를 넣습니다.
  - 예) Tasker: 본문 `%sms_body`, 발신 `%sms_from`
  - 예) MacroDroid: 본문 `[sms_message]`, 발신 `[sms_number]`
- **`device`** 에는 그 폰을 알아볼 **라벨**을 적습니다. (예: `대표폰`, `경리폰`)
  - **폰마다 다른 라벨**을 넣어야 어느 폰에 온 문자인지 구분됩니다.

---

## 4단계 — 확인

문자를 하나 받아본 뒤:

- 인증번호 문자 → **[인증번호]** 화면에 표시
- 입금 문자 → **[입금관리]** 목록에 표시 (계좌 끝 4자리 포함)
- 카드 문자 → **[카드사용내역]** 목록에 표시

분류가 안 되는(지원 안 된 은행/카드사) 문자도 **서버에 원문이 보관**되어, 나중에 패턴을 추가하면
다시 분류할 수 있습니다. 유실되지 않습니다.

---

## 참고

- **지원 형식(현재 테스트 버전)**: 쿠팡 등 인증번호, 삼성카드 승인, 기업은행 입금.
  다른 카드사·은행·서비스는 실제 문자가 쌓이는 대로 패턴을 추가하면 됩니다.
- **중복 방지**: 같은 문자가 두 번 전송돼도 한 번만 저장됩니다.
- **보안**: 인증번호는 비밀번호에 준하는 민감 정보입니다. 전달 대상 폰·계정 관리에 유의하고,
  인증번호는 48시간 뒤 자동 삭제됩니다.
